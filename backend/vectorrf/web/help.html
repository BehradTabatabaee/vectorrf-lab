USER GUIDE

VectorRF Lab

VectorRF Lab is a local, browser-based baseband DSP laboratory. The transmitter, spectrum analyzer, receiver, frame tools, classifier and radar workspace operate on simulated complex samples rather than a hardware RF front end.

Fast path: choose a waveform in Transmitter, set sample rate and power, then open Spectrum or Receiver. Most edits apply when a field loses focus or you press Enter.

What the status bar means

SOURCE identifies the active simulation path, FS is the current sample rate, UPDATE is the observed browser display rate, and the right side reports current state or validation errors. A display rate below its target means the requested experiment is taking longer than one frame budget.

Spectrum analyzer

The communications spectrum is always centered at baseband DC; there is no analyzer center-frequency control. Baseband span controls the horizontal display span and is limited to 10 MHz.

The requested span and the source sample rate are intentionally separate. A 10 MHz display span always shows approximately −5 MHz to +5 MHz. If the source is only 1 MS/s, valid sampled spectrum exists only inside approximately −500 kHz to +500 kHz; the remainder is marked OUTSIDE SOURCE NYQUIST. Increase transmitter sample rate when you need real spectrum data across the wider span.

Resolution and speed

Requested RBW, FFT window and averaging determine FFT cost. Narrow RBW at a high sample rate requires a larger transform. The live path limits display points while preserving bucket peaks so a wide 10 MHz view does not need to draw every FFT bin.

Markers and zoom

Up to eight markers can be active. Use peak, next-peak, DC, delta-to-M1 and DC↔peak actions for common measurements. Mouse-wheel zoom is centered on the pointer; the pan controls move the view without retuning acquisition. Double-click restores the full requested span. Markers remain constrained to sampled data, so they cannot report a fabricated value outside source Nyquist.

Trace memory

Trace 1 is the live write trace by default. Additional max/min/average traces are off until enabled to keep the default rendering path fast. Capture memory stores frequency coordinates together with trace values, allowing comparisons after later configuration changes.

Zero span

Zero span plots time-domain I/Q, envelope, unwrapped phase and instantaneous frequency from one interval of the current source. Frequency is calculated from adjacent complex samples before display reduction, and phase/frequency values around signal nulls are masked because they are undefined there.

The live zero-span view is intentionally bounded to a display-sized point set and refreshes independently from the spectrum FFT stream. Use Hold capture when inspecting a transient. Shorter measurement lengths reduce both compute and browser drawing work.

Absolute transmitter power

Transmit power (dBm) is an absolute simulator calibration and has no artificial UI min/max limit. A coherent bin-centered complex tone reads its configured dBm value at the spectrum peak. Modulated signals have the same configured average total power distributed over their occupied bins, so no single spectral bin is expected to equal total transmit power.

This is a simulation calibration, not a hardware output-power claim. It does not model DAC full scale, analog gain compression, antenna gain, cable loss or regulatory transmit limits unless a separate experiment explicitly introduces those effects.

Generic TX and RX frames

The transmitter frame builder can assemble ordered digital blocks with independent modulation, bit count or pattern, symbol rate, relative power and repetition. Supported frame blocks include PSK/QAM/APSK, FSK/MSK/GMSK and OFDM families. Blocks repeat as a complete frame to fill the capture.

The receiver framing view uses an expected block plan. It can perform calibrated energy detection, normalized preamble correlation, frame-start selection and per-block decoding. Follow transmitter is useful for loopback experiments; editing the receiver frame plan independently disables that linkage.

Typical lab frame: BPSK preamble → OFDM header → QPSK payload. Use the preamble for correlation, then inspect each decoded block separately.

Receiver

Live monitor shows the actual processed samples without requiring a demodulation assumption. Demodulation adds format-specific recovery. The editable processing chain can insert gain, tuning, filtering, resampling, DC removal, AGC, expressions, synchronization blocks and supported Python extensions.

Channel controls add deterministic SNR, carrier/phase/timing offsets, I/Q imbalance, DC and echo effects. For repeatable experiments, capture identity and source seed are carried through the processing path.

Modulation quality

Linear digital and OFDM formats use decision-directed EVM/MER where meaningful. Basic, analog, FSK/MSK and mixed-frame signals instead show direct waveform quality: I/Q trajectory, envelope, phase and instantaneous frequency. The application does not invent an EVM number for a signal type where that metric is not defined.

Classifier

The classifier is a blind heuristic observer. Its score indicates agreement with internal rules, not a calibrated probability. CFO, low SNR, burst behavior, mixed frames and uncommon formats can reduce confidence or make different hypotheses look similar.

Radar Studio

Radar Studio is a separate simulation workspace with waveform design, targets, arrays, propagation and processing. It supports arbitrary-waveform delay/Doppler correlation plus structured pulsed and FMCW processing. Truth values and measured estimates are shown separately.

Keep designed baseband content below half the configured sample rate to avoid aliasing. Coherent processing requires enough complete intervals for the requested algorithm; timing controls should match the waveform being simulated.

Performance guide

VectorRF Lab uses bounded binary spectrum payloads, backpressure, cached source records, display decimation and request coalescing. The fastest configuration is normally one live trace, moderate averaging and an RBW that does not force an unnecessarily large FFT.

Limits and validation

Invalid edits retain the last successful live result. The spectrum span field clamps typed values to the supported 100 Hz…10 MHz range, so entering 50,000,000 becomes 10,000,000 rather than killing the stream. Direct API clients still receive validation errors for unsupported values.

The transmitter sample rate is currently limited to 10 MS/s. Spectrum content above ±Fs/2 is not available from that sampled source. Numeric controls allow arbitrary valid typed values; arrow buttons are only convenience increments.

Troubleshooting

The spectrum axis is wide but the trace only occupies the middle

The requested span is wider than the transmitter sample rate. This is expected and is explicitly shaded. Increase sample rate if you need sampled content across the full span.

A PSK/QAM spectrum appears to jump

Current releases avoid wrapping FFT windows across source-record boundaries. If you still see a change, check burst settings, noise, changing data, detector mode and peak/max-hold traces before treating it as a renderer problem.

The browser says the backend is unavailable

Keep the launch terminal open and verify the local server is listening on the configured port. The default address is http://127.0.0.1:8765. Set VECTORRF_PORT before launch to choose another port.

How do I verify a release?

From the project directory run python -m pytest. The release archive also includes browser smoke tests and release notes. Installed packages can be launched with vectorrf-lab.
